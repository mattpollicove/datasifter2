# AI-assisted development

AI coding assistants have been used as development aids for understanding the
codebase, proposing and implementing changes, drafting or updating tests,
reviewing changes, troubleshooting, and preparing documentation. The level of
assistance varies by task; this does not mean that all project code was
generated by AI. AI output is a suggestion, not an authoritative source or a
substitute for maintainer judgment.

Contributors remain responsible for reviewing AI-assisted changes for
correctness, security, privacy, licensing, and compatibility. Use the relevant
tests, linters, and build checks; generated tests and AI explanations do not by
themselves establish that a change is correct or complete. Follow the project
guidance in [CONTRIBUTING.md](./CONTRIBUTING.md) for review and validation
evidence.

Do not include passwords, tokens, private keys, production directory entries,
or other sensitive information in AI prompts. Use sanitized examples and only
approved coding-assistant tools and settings. Depending on the tool and its
configuration, project excerpts submitted in prompts may be processed under
the provider's data-handling terms; contributors should review those terms and
settings before use.

The repository's [AI build prompts](./datasifter_prompt_AI.md) provide
project-specific guidance for staged, verifiable AI-assisted work.

This development practice is separate from DataSifter's optional user-facing
AI feature, Directory Lens. Directory Lens uses a locally selected GGUF model
through llama.cpp to draft LDAP search filters; see the [README](./README.md)
and [privacy notice](./PRIVACY.md) for product behavior and data handling.
